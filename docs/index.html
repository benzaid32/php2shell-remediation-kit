The gap

The patch is the easy part. Proving it is the work.

Most teams can run an update. Few can show which PHP runtime is actually serving traffic, whether a distro backport is real, and whether the web SAPI is still one config change away from the vulnerable path.

01

PHP is not WordPress

Updating WordPress, plugins, or themes does not update the PHP runtime underneath. The bug is in PHP itself.

02

Version strings can lie

Distributions backport fixes without changing the upstream version. php -v alone is not patch evidence.

03

The web SAPI is a different config

memory_limit=-1 in CLI does not mean Apache or FPM is safe. Effective values live in pools, vhosts, and per-directory overrides.

04

Containers hide old runtimes

Restarting an old image keeps the old PHP inside it. Rebuild from a patched base and verify the final image, not the compose file.

FAQ

Straight answers.

If your question is not here, ask it in the triage call. We will tell you if we are not the right fit.

Do you scan our website?

No. We work on hosts you own or are explicitly authorised to administer. The free scripts are read-only and run locally. Paid engagements start with a written scope that names the hosts and allowed actions.

We already patched PHP. Why verify?

Because the version string is not the whole story. The web SAPI can use a different INI file, a distro may have backported the fix without changing the upstream version, and a container may still run an old image. Verification ties the evidence to the runtime that actually serves traffic.

Is this a WordPress issue?

No. WordPress runs on PHP, but the vulnerability is in PHP itself. Updating WordPress, themes, or plugins does not patch the PHP runtime.

Does a WAF fix it?

No. A WAF can reduce some attack paths and buy time, but it is not a complete fix. The only full remediation is a patched PHP runtime.

What if we suspect a compromise?

Treat it as an incident: isolate the host, preserve evidence, rotate credentials, and rebuild from a known-good image. We can scope incident response separately; do not wait for a sales call to take containment steps.

How do you handle sensitive data?

We minimise collection, use read-only evidence where possible, and never ask for passwords in the contact form. A paid engagement includes a written scope, confidentiality terms, and a data-handling agreement before access.

Do you work with agencies and MSPs?

Yes. The retainer is built for firms managing multiple client sites. We can produce white-label evidence reports and act as a priority escalation path for new PHP advisories.
